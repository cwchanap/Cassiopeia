# HPA-1311 — Enemy AI for Turn-Based Battles (Implementation Plan)

**Design:** [Enemy AI design](../specs/2026-11-25-hpa-1311-enemy-ai.md)  
**Linear:** [HPA-1311](https://linear.app/cwchanap/issue/HPA-1311/enemy-ai-for-turn-based-battles)  
**Base:** `main` at `cf7c52942251e2046d3d926c03e406d76d3ad98b`.  
**Status:** Proposed; implementation and acceptance not yet performed.  
**Delivery:** One PR, initially draft; add all implementation and evidence to this PR.

## Working approach

Read CLAUDE.md, the HPA-1310 rules design and the new AI design. Preserve the
existing pure simulation boundary. The HPA-1310 module is on main: its immutable
reducer, legal query contracts, content catalogs and exact events already suffice
for the planner. The only permissible shared-rule refactor is extracting the
directional classification to reuse it, with no changes in damage behavior.

Use the existing server/Node Vitest project. Keep tests small and deterministic.
Use one implementation branch and one PR. No new dependencies or feature flags.
Do not wire AI into GameMode, stepGame, runtime, renderer, input, HUD or saves;
HPA-1315 does that. Art and sound are already separately tracked.

## Slice 1 — Data and pure turn enumeration

Files (relative to `src/lib/game/simulation/battle/`): `types.ts`, `content.ts`,
`ai.ts`, `index.ts`, `ai.spec.ts`.

- [ ] Define closed AiArchetypeId, readonly numeric weight records and
  BattleAiProfile (guardian requires a post). Keep archetype catalog frozen like
  MOVES and INTERNAL_ARTS. The planner must be pure and usable by either side.
- [ ] Implement the active-actor/phase checks and standable guardian-post
  validation. Enumerate stay plus every available move destination; apply real
  move commands to produce candidate states. A moved actor can only stay.
- [ ] Enumerate owned slots and getMoveTargets for each speculative state;
  enumerate every returned aim, Guard and Gather. Do not enumerate enemy
  useItem, and do not add a squad item strategy. Resolve candidate actions using
  applyBattleCommand and preserve ordered reducer events for scoring only.
- [ ] Represent a candidate locally (commands, movement cost, action result,
  ordering keys); avoid exporting internal scoring or candidate types. Add
  endTurn only if the original living actor is still active in an ongoing battle.
  For hasActed, generate only endTurn. Apply/validate the winning endTurn through
  the public reducer; return copied cell coordinates.
- [ ] Tests: terminal/wrong actor, already moved, already acted, stay is not a
  move, unique legal moves/aims, obstacles and terrain costs, unaffordable moves,
  no attack available, no enemy item consumption even with squad pills, deep-
  frozen input, no aliasing, all returned commands replay legally. Check
  candidate coverage with controlled fixtures where the unique best move is
  away from the initial cell, and where a line/arc aim hits multiple enemies.
  No new debug API solely for tests.

## Slice 2 — Scoring and archetypes

Files: `ai.ts`, `content.ts`, `ai.spec.ts`; `grid.ts` / `rules.ts` only if needed
for a shared pure directional helper. Keep all policy differences as data.

- [ ] Score actual applied damage, kills, weak targets, flank, counters, terminal
  outcome, actual Gather gain and qi cost from the accepted action's state/events.
  Rank immediate victory/defeat relative to actor side, not hero perspective.
  Ignore dead fighters for positioning; penalize nonterminal self-defeat.
- [ ] Score bamboo, nearest-hostile preferred range, adjacency and guardian post
  distance. Use the design's initial weight table, tune with behavior fixtures.
  No separate decision tree for each archetype, no random numbers or tactical
  lookahead.
- [ ] Estimate threat from each living hostile with explicit-ID getReachableCells
  plus legalAimCells/affectedCells and its affordable owned moves. Count distinct
  opponents once, including each opponent's possible rear attack origins for each
  facing; use the shared cardinal direction classification. Reuse geometry per
  origin/move and the same threat summary across facings and equal layouts within
  one decision. Never mutate state or simulate future turns to get a threat.
- [ ] Implement fixed comparator: terminal rank, score, less qi, cheaper
  movement, destination z/x, action slot/order, aim z/x, current facing then
  N/E/S/W. Confirm ties remain identical across repeated/JSON-round-trip calls.
- [ ] Test Aggressor advancing into range, picking a weaker equally reachable
  target and exploiting side/rear; Marksman using Willow Darts, preferring
  standoff, choosing cover and avoiding adjacent enemies; Guardian remaining
  near a supplied post, guarding when threatened rather than wasting qi, and
  striking a nearby vulnerable target. Tests assert behavior, not arbitrary
  exact coordinates unless testing tie-breaking.
- [ ] Add focused discriminating tests: all four facing candidates, a blocked
  ray versus water and bamboo, movement exposure across weighted/occupied
  cells, dead threats excluded, multiple threats counted once per opponent,
  counter loss and guard-ignoring move, zero-gain Gather versus meaningful
  Gather, no attacks on allied targets, and stronger multi-hit choice.
  Include a lethal counter that auto-hands off to another living fighter
  without a stale endTurn and a terminal attack with no endTurn. Regression
  tests retain all existing directional percentage behavior if refactored.

## Slice 3 — End-to-end headless battle and performance

Files: `ai.journey.spec.ts`, `ai.perf.spec.ts` (or a focused opt-in benchmark
invoked by Vitest), plus any local fixture helpers. Test through `index.ts` only.

- [ ] Author a reachable 12 x 12 mixed-terrain scenario with at least two
  fighters per side using starter templates/arts, including different
  archetypes; include a guardian post and a marksman. Empty squad bag.
  Use only createBattle, getTurnOrder, planBattleTurn and applyBattleCommand
  for the battle loop. A second small Lu/hero duel is a useful spar integration
  fixture. Do not manually mutate HP/qi to force a journey outcome.
- [ ] On each turn, plan for activeId and replay the returned commands; assert
  all accepted, at most one move and one action, and that a surviving actor
  hands off or wraps to its next round with the expected turn events. Ensure
  a terminal action or counter-kill hands off without stale commands. Require
  one real battleEnded event, victory with zero living enemies or defeat with
  hero HP zero, and no active actor at the end. Fail if an ongoing fixture
  exceeds 200 planned turns (test safety limit, not a rules cap).
- [ ] Replay from a fresh setup and a per-command JSON-round-tripped state;
  compare command transcript, event transcript and final state for exact
  equality. Include a reachable obstacle detour in a small behavior fixture.
  Tune weights if the representative journey stalls; do not weaken tests or
  add forced outcomes to production. The policy is not guaranteed to solve
  disconnected or pathological maps.
- [ ] Measure planner only (exclude fixture setup, rendering and executing
  commands) on an authored 16 x 16 map with twelve living fighters (six per
  side), bamboo, water and obstacles, an active fighter with a normal starter
  movement budget and multiple enemies in potential attack reach. Exercise
  each archetype on equivalent relevant fixtures, including a ranged/area
  move and counter/guard threat. Warm up at least 30 decisions; collect at least
  100 timed decisions per archetype. Assert legal/non-empty commands and
  document fixture, candidate count or reachable-cell count, runtime, host,
  median, p95, max. Target warmed p95 <= 16.7 ms per decision (60 Hz).
  The benchmark is opt-in/report-only for noisy timing in CI; run it via
  execution MCP and record actual numbers. If it misses, profile, reuse
  per-decision geometry/occupancy summaries and rerun; don't prune legal
  candidates, change the fixture into an empty map or silently waive the target.

## Acceptance checklist (must be evidenced, not merely asserted)

- [ ] Every legal move destination (including stay), owned affordable attack
  aim, Guard, Gather and legal final facing is evaluated; decisions replay
  through the unmodified command rules, never a duplicate damage engine.
- [ ] Three archetypes have distinct behavior confirmed by deterministic unit
  fixtures. Threat, terrain, facing, counter and phase regressions pass.
- [ ] Through execution MCP, a public-API AI-vs-AI battle with both sides
  controlled by the planner ends naturally within 200 planned turns, all
  commands accepted; full fresh/JSON-round-trip replays are equal.
- [ ] Through execution MCP, the 16 x 16 / twelve-fighter decision benchmark
  meets the documented p95 one-frame target, with measurements attached.
- [ ] `bun run check`, `bun run lint`, and `bun run test` pass on the final
  implementation head; no rules-engine regression.
- [ ] Existing web exploration screenshot inspected via MCP for visual
  regression; no new UI or asset requirements and no human acceptance step.
- [ ] A single PR contains the spec, plan, implementation, tests and evidence.
