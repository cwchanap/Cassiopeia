# HPA-1311 — Enemy AI for Turn-Based Battles (Implementation Plan)

**Design:** [Enemy AI design](../specs/2026-11-25-hpa-1311-enemy-ai.md)  
**Linear:** [HPA-1311](https://linear.app/cwchanap/issue/HPA-1311/enemy-ai-for-turn-based-battles)  
**Base:** `main` at `cf7c52942251e2046d3d926c03e406d76d3ad98b`.  
**Status:** Implementation complete; final acceptance evidence is pending — fresh CI on the
final head and the PR evidence update happen after push, and the PR stays untouched until then.
The shipped catalog weights are the design's initial values — the journey and behavior fixtures
passed without retuning, so no weight, scan-order or fixture changes were needed.  
**Delivery:** One PR, initially draft; add all implementation and evidence to this PR.

## Working approach

Read CLAUDE.md, the HPA-1310 rules design and the new AI design. Preserve the
existing pure simulation boundary. The HPA-1310 module is on main: its immutable
reducer, legal query contracts, content catalogs and exact events already suffice
for the planner. The only shared-rule refactors are extracting the existing accepted-attack
forecast projection and directional classification and exposing movementBudget
within the battle module. Do not export these helpers from the public barrel
or change damage, movement budget, command, forecast or turn semantics.

Use the existing server/Node Vitest project. Keep tests small and deterministic.
Use one implementation branch and one PR. No new dependencies or feature flags.
Do not wire AI into GameMode, stepGame, runtime, renderer, input, HUD or saves;
HPA-1315 does that. Art and sound are already separately tracked.

## Slice 1 — Data, pure turn enumeration and early battle harness

Files (relative to `src/lib/game/simulation/battle/`): `types.ts`, `content.ts`,
`ai.ts`, `index.ts`, `ai.spec.ts`, `ai.journey.spec.ts`, `rules.ts`.

- [ ] Define public `AiArchetypeId`, `BattleAiProfile` and readonly
      `AiArchetypeWeights` in types.ts with the design's named fields. Define
      `AI_SHARED_WEIGHTS` and
      `AI_ARCHETYPES: Readonly<Record<AiArchetypeId, AiArchetypeWeights>>`
      in content.ts; deep-freeze both using the existing helper. These are
      intentionally public through the existing barrel; export only the new
      planBattleTurn function from ai.ts via index.ts.
- [ ] Validate profile unconditionally before the terminal/active-actor checks:
      fail clearly for missing profile, non-member archetype (own key or closed
      literals), missing Guardian post or non-standable/non-integer post.
      Reuse canEnterTerrain(terrainAt(map, post)) after presence checks.
      Occupied ground/bamboo is a valid post. Only a valid profile permits
      returning [] for terminal/dead/unknown/inactive actors. Enumerate stay
      plus every legal move in stable cost/discovery order; apply real move
      commands to produce candidate states. A moved actor can only stay.
- [ ] Enumerate owned slots and getMoveTargets for each speculative state;
      enumerate every returned aim, Guard and Gather. Do not enumerate enemy
      useItem, and do not add a squad item strategy. Resolve candidate actions using
      applyBattleCommand. Extract summarizeAttack from forecastMove in rules.ts;
      keep the helper internal to the battle module (not in index.ts). Use the
      same accepted attack result for forecast projection and scoring. Existing
      forecast tests must remain unchanged in behavior.
- [ ] Represent a candidate locally (commands, action result, rank, score); avoid exporting internal scoring or candidate types. Add
      endTurn only if the original living actor is still active in an ongoing battle.
      For hasActed, generate only endTurn. Apply/validate the winning endTurn through
      the public reducer; return copied cell coordinates.
- [ ] Tests: public barrel exports, frozen catalogs, invalid profile/post
      (missing, unknown archetype, fractional, out of bounds, water, obstacle),
      valid occupied ground/bamboo posts, rejection before terminal/inactive/
      dead/unknown actor short-circuit, valid profile returns [] on these states,
      already moved, already acted, stay is not a
      move, unique legal moves/aims, obstacles and terrain costs, unaffordable moves,
      no attack available, no enemy item consumption even with squad pills, deep-
      frozen input, no aliasing, all returned commands replay legally. No new
      debug API solely for tests. Start with a minimal attack/approach score,
      then implement the full integer score in Slice 2.

- [ ] Build the public-API journey harness now, before tuning. Author a reachable
      12 x 12 mixed-terrain battle (at least two fighters per side, mixed archetypes,
      Guardian post and Marksman; empty bags) and two actual starter-stat mutual-
      reach hero/Lu duels (Aggressor hero versus Aggressor Lu, and versus Guardian
      Lu at his starting post). Full starting HP/qi, opposing facings, no forced
      damage or scripted commands. Use createBattle, getTurnOrder, planBattleTurn
      and applyBattleCommand only. Each command must be accepted; verify handoff
      and at most one move/action. Fail after 200 planned turns if still ongoing
      (test-only bound). Require real battleEnded exactly once, valid outcome,
      no active actor, and actual HP reduction by the end of round 4 in each duel.
      Write the assertions before full scoring, run with the minimal scorer to
      expose stalls, then keep the fixtures running throughout Slice 2. Final
      acceptance requires all three battles to pass, not a skipped or weakened
      test. Replay the mixed battle from fresh and JSON-round-tripped states;
      compare command/event transcripts and final state exactly.

## Slice 2 — Threat map, integer scoring and archetypes

Files: `ai.ts`, `content.ts`, `ai.spec.ts`, `ai.journey.spec.ts`, `rules.ts`.
Reuse the existing grid.ts helpers without introducing rule-specific damage
percentages into grid.ts.

- [ ] Build a single actor-excluded threat map with computeReachableCells from
      grid.ts, existing movementBudget from rules.ts (export within the module
      only), legalAimCells/affectedCells and affordable owned moves after capped
      qi regeneration. Pass occupied cells from all living fighters except the
      hostile being evaluated and the acting fighter; never use explicit-ID
      getReachableCells for this approximate map. Record unique origins per
      hostile and threatened cell; filter killed hostiles at lookup. All
      destinations, including stay, use the same actor-excluded geometry.
      Candidate destinations may be traversed and non-actor casualties may
      remain blockers in this estimate. Actual commands remain exact. No
      persistent cache, pruning or per-candidate reachability. Extract the
      shared facingPercentFor classification in rules.ts with hypothetical
      cell/facing parameters; preserve diagonal ties and damage semantics.
- [ ] Score actual primary hits, kills, weak targets, flank, counters, qi
      cost, Gather gain and outcome. Use summarizeAttack for attacks (one reducer
      call, same projection as forecastMove). Rank immediate win/defeat relative
      to actor side; ignore dead fighters for positioning. Use shared integer
      weights and archetype-specific integer weights from the design, floor
      the missing-health fraction contribution; no float score comparison.
- [ ] Score bamboo, nearest-hostile preferred range from archetype data,
      adjacency, post distance, threat count, possible rear origins and current
      hostile directions. One formula, not a decision tree per archetype.
      Compare terminal rank then integer score, retaining the first on ties:
      stay, cost/discovery-ordered destinations, owned slots/aim query order,
      Guard, Gather, current facing then remaining N/E/S/W.
- [ ] Tune against the early battle harness first. Start with Aggressor Guard
      bonus 0 and reduced counter penalty; Guardian's positive bonus is lower
      than a clean starter basic hit. Guard remains a legal candidate for all
      profiles. Verify both mutual-reach spar fixtures make HP progress and end,
      and the mixed battle ends naturally. Do not change starter stats or add a
      production cap; tune weights or use simple spatial approach tie-break only
      if needed. No guarantee for disconnected or pathological layouts.
- [ ] Test Aggressor closes in, prefers the weaker of otherwise equal targets
      and exploits flank; Marksman prefers standoff, cover and avoids adjacency;
      Guardian holds its post, guards against threats and punishes an approaching
      vulnerable opponent. Test reachable obstacle detour. Assert behavior, not
      arbitrary coordinates except for deterministic scan-order ties. Confirm
      unique best destination away from start and multi-hit line/arc choice.
- [ ] Focused tests: four facings (including diagonal classification), terrain
      and occupied-cell movement, obstacle-blocked ray versus water/bamboo, the
      documented actor-excluded approximation (hostile at 2,2 with budget 3,
      Marksman at 3,2; origin 5,2 threatens 6,2 via Sword Cut, and the map is
      invariant before/after a legal actor-only move), symmetric stay/lateral
      occupancy, other living blockers, distinct threat counts and killed
      hostile filtering, Guard/counter and ignoreGuard, actual vs zero Gather,
      no allied attacks, terminal action, non-terminal counter kill/auto-handoff
      with no stale endTurn, repeatability and JSON replay. Run existing battle
      tests, including forecast parity, to prove shared helper extraction did
      not change rules. No duplicate combat math.
